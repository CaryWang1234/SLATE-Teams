1 SLATE Teams 是什么？What is SLATE Teams?

SLATE Teams 是一款本地优先的 AI 协作调度台。它把主流大模型、35 个内置工具、团队辩论、DAG 工作流、白板式逻辑链整合在一个轻量界面里——零 npm、零构建、开箱即用。

核心理念：让灵感直达行动，中间不隔工具摩擦。

SLATE Teams is a local-first AI collaboration studio. It integrates mainstream LLMs, 35 built-in tools, team debates, DAG workflows, and whiteboard logic chains — all in a lightweight interface. Zero npm, zero build, ready to use.

Core philosophy: Let ideas go straight to action, without tool friction in between.
2 安装与启动Installation & Quick Start

方式一：安装包（推荐）

前往 GitHub Releases 下载 SLATE-Teams-Setup-x.x.x.exe，双击安装即可。

装好后点窗口右上角的 X 不会结束应用：SLATE Teams 缩进系统通知区域继续跑，正在生成的那一轮照常收工，手机端的局域网连接也不掉。双击托盘图标（或右键「显示主窗口」）找回窗口，右键「退出 SLATE Teams」才真的退出，第一次缩下去会弹一条气泡提示。托盘只用 Windows 原生 API 实现，不引入第三方依赖；非 Windows、或这个登录会话根本没有通知区域时，关窗退回原来的直接退出。

同一份安装只会开一个 SLATE Teams 窗口：窗口已经开着、或者已经缩进通知区域时再双击一次图标，不会多出一个窗口、也不会多起一份后端——新进程会把正在跑的那个窗口唤回前台（抢不到前台时让任务栏图标闪一下），然后自己退掉。锁随进程消失，崩溃或被任务管理器结束都不会把应用变成「再也打不开」；装到另一个目录的副本算另一份安装，可以与这一份同时跑。

macOS

前往 GitHub Releases 下载 SLATE-Teams-Setup-x.x.x.dmg，双击挂载后把「SLATE Teams」拖进「应用程序」。这个 .dmg 由 CI 直接产出，只做了 ad-hoc 签名、没有公证，首次打开会被 Gatekeeper 拦一次：在访达里右键（或长按）图标 → 「打开」 → 再点一次「打开」，此后就能双击启动。如果对话框写的是「已损坏，无法打开」（只有「移到废纸篓」，没有「打开」按钮），说明系统没认到签名，改用这条命令去掉隔离标记再打开：sudo xattr -dr com.apple.quarantine "/Applications/SLATE Teams.app"。

安装版的数据不在 .app 包里，而在 ~/Library/Application Support/SLATE Teams：对话历史、API Key、后端日志和 WebView 的个人资料都在这里。替换 .app 升级不会动你的数据，包体也不会在运行时被写脏——将来真签名公证时，那种改动是会废掉签名的。源码运行仍然把数据放在仓库的 data/。

窗口用 macOS 原生的 WKWebView 渲染，Windows 用 Edge WebView2，两套内核各自的偏好与缓存互不相通。「设置 → 关于」里的检查更新在 Mac 上给出的是这一平台的 .dmg 链接，不会推一个双击打不开的 .exe；发布产物里找不到匹配文件时退回 Releases 页面。

键盘上 ⌘ + N 新建对话、⌘ + D 切换明暗，Ctrl 组合同样有效；焦点在白板画布里时 ⌘ + D 归给「复制选中的卡片」这条绑定，不会去翻明暗。界面正文走系统字体（苹方），代码走 SF Mono / Menlo，Windows 上仍是微软雅黑与 Consolas。

高危命令的清单按平台补齐：diskutil erase、diskutil reformat、diskutil partitionDisk、diskutil secureErase（抹盘、重分区）会先弹审批；rm -rf /、rm -rf ~、mkfs、dd if= 这类灾难级命令无条件禁止，连审批都不走。

Mac 上还没有这两件事：通知区域常驻与「一份安装只开一个窗口」目前只在 Windows 上实现——关窗口就是退出，重复启动会再起一份。另外，这一轮 macOS 改动是在 Windows 上把「平台」当实参、将 Darwin 分支执行并断言验证的，.app 与 .dmg 尚未在真机上跑过。

Option A: Installer (Recommended)

Download SLATE-Teams-Setup-x.x.x.exe from GitHub Releases and run the installer.

On Windows, clicking X does not quit the app: SLATE Teams hides into the notification area and keeps serving, so the turn that is generating finishes and LAN clients stay connected. Double-click the tray icon (or right-click → "Show window") to bring the window back; only "Quit SLATE Teams" actually exits, and the first time it hides a balloon tells you where it went. The tray uses Windows native APIs only and adds no third-party dependency; off Windows, or in a logon session with no notification area, closing the window exits exactly as before.

One install opens exactly one SLATE Teams window: if the window is already open, or already hidden in the notification area, launching again adds no second window and starts no second backend — the new process brings the running window to the front (flashing its taskbar icon when Windows refuses the foreground) and then exits. The lock disappears with the process, so a crash or a kill in Task Manager never leaves the app "unable to open again"; a copy installed into a different folder counts as a different install and may run alongside this one.

macOS

Download SLATE-Teams-Setup-x.x.x.dmg from GitHub Releases, mount it, and drag "SLATE Teams" into "Applications". The .dmg comes straight out of CI and is ad-hoc signed but not notarised, so Gatekeeper stops the first launch once: right-click (or long-press) the icon in Finder → Open → Open again. A plain double-click works from then on. If the dialog instead reads "「SLATE Teams」已损坏，无法打开" (only a "Move to Trash" button, no "Open"), the signature was not picked up — clear the quarantine flag first: sudo xattr -dr com.apple.quarantine "/Applications/SLATE Teams.app".

An installed build keeps its data outside the .app, under ~/Library/Application Support/SLATE Teams: chat history, API keys, the backend log and the WebView profile. Replacing the .app to upgrade leaves your data alone, and the bundle is never written to at runtime — the kind of change that would void a signature once the app is signed. Running from source still uses data/ inside the repo.

The window renders through macOS-native WKWebView while Windows uses Edge WebView2; the two engines keep their own preferences and caches apart. "Check for Updates" under Settings → About hands you the .dmg link for this platform rather than an .exe you cannot open, and falls back to the Releases page when no matching asset is published.

⌘ + N starts a new chat and ⌘ + D toggles light/dark; the Ctrl chords keep working too. With focus inside the whiteboard canvas, ⌘ + D belongs to its duplicate-selected-cards binding and does not flip the theme. UI text uses the system font (PingFang SC) and code uses SF Mono / Menlo, where Windows stays on Microsoft YaHei and Consolas.

The dangerous-command list is now platform-aware: diskutil erase, diskutil reformat, diskutil partitionDisk and diskutil secureErase ask for approval first, while catastrophic ones — rm -rf /, rm -rf ~, mkfs, dd if= — are refused outright, approval or not.

Mac does not have two things yet: notification-area residency and the "one install, one window" gate are Windows-only, so closing the window quits and launching again starts a second copy. Also note that this round of macOS work was verified on Windows by passing the platform in as an argument and asserting the Darwin branches — the .app and .dmg have not been run on real hardware.

3 多模型对话Multi-Model Chat

SLATE Teams 支持同时接入多个模型，在对话界面顶部下拉框随时切换。

  • 点击模型下拉框 → 添加/切换模型
  • 不同对话可使用不同模型
  • 支持本地模型（Ollama / LM Studio 的 OpenAI 兼容端点）
  • 模型名旁边画品牌 mark：内置模型与自己添加的模型都按名字认，认得出的按品牌自己的颜色画（没有彩色原件的画中性灰单色），认不出就什么也不画，不会拿别人的 logo 顶替；自定义主题不会把品牌色染掉
  • 每条回复显示模型名称与 Token 用量
快捷键：Enter 发送 · Shift+Enter 换行 · Ctrl+N / ⌘N 新建对话 · Ctrl+D / ⌘D 切明暗
＋ 模式菜单：输入框左侧的 ＋ 按钮集中了模式入口 —— 磨墨 / 头脑风暴 / 目标模式 / 定时任务，以及「提及」分组（技能 / 工具 / MCP / 文件），点击行即可启动对应模式或弹出对应候选列表。菜单钉在 ＋ 按钮上方：再按一次 ＋、点菜单外面或按 Esc 都会收起。
思考强度滑杆：点输入框左侧的档位胶囊弹出滑杆，刻度只列当前模型支持的档位（自动 / 关 / 低 / 中 / 高），每档下方以小字标注对应墨色（随墨 / 清墨 / 淡墨 / 浓墨 / 焦墨），拖动时只预览、松手才生效并落盘。刻度不是照抄一份固定表：SLATE Teams 按端点能力分了九类，强制思考的模型没有「关」这一档；只分开关的端点在档位旁注明「低 / 中 / 高都按开」；这个模型接不住的刻度直接置灰并写明原因，切模型那一刻也会在弹窗里提示。上游若以 400 点名该字段，会剥掉它重发一次——最坏是这次档位不生效，而不是模型用不了。
上下文预算：设置页「模型配置」里每个模型一行「最大上下文」，由按该模型窗口生成的滑杆、精确数字框、以及「探测窗口」按钮三件组成。「自动」取这个模型自己的标称窗口 ×0.8，不再吸附公共档位——只有 8K 窗口的本地模型过去只能凑不满最低一档、等于把窗口占满没地方写回复，现在拿到 6553。数字框保留你填的精确值（131072 就是 131072，只在 1K–4M 内夹取）。Ollama / llama.cpp / vLLM / OpenAI 兼容这类本地或自定义端点可以一键探测真实窗口，探到的值单独存一张覆盖表，随时能一键清除回到端点自带值。同一个值肩挑两件事——自动压缩的触发阈值与用量条的分母，所以读数不会和压缩时机各说各话；用量条可以直接点，点了跳到对应模型的这一行。
历史摘要折叠条：超过阈值后，较早的对话会被压成一段摘要。摘要本身仍按原格式完整发给模型，只在消息区折叠成一条——点标题展开才解析 Markdown，长历史不会把当前几轮挤出屏幕。

SLATE Teams supports multiple models simultaneously — switch anytime from the top dropdown.

  • Click model dropdown → Add/switch models
  • Different conversations can use different models
  • Supports local models (Ollama / LM Studio via OpenAI-compatible endpoints)
  • A brand mark sits beside the model name: built-ins and models you add are matched by name; recognised ones are drawn in the brand's own colours (neutral monochrome where no colour original exists), and an unknown one draws nothing instead of wearing another vendor's logo. A custom theme won't recolour them
  • Each reply shows model name and token usage
Shortcuts: Enter to send · Shift+Enter for newline · Ctrl+N / ⌘N new conversation · Ctrl+D / ⌘D light-dark
＋ Mode Menu: The ＋ button left of the chat input centralizes mode entries — Grind / Brainstorm / Target Mode / Scheduled Tasks — plus an @-mention group (Skills / Tools / MCP / Files) that opens a filtered picker. The panel is anchored above the ＋ button: press ＋ again, click outside, or hit Esc to dismiss it.
Reasoning slider: Click the level pill left of the input to open a slider whose ticks list only what the current model supports (auto / off / low / medium / high). Each tick carries its ink shade in small type (free / clear / light / rich / charred); dragging previews, letting go applies and persists. Those ticks are not a copied fixed table: SLATE Teams sorts endpoints into nine capability classes, so a model that forces reasoning has no "off" tick, on/off-only endpoints say "low/medium/high are all treated as on", and a tick this model cannot take is greyed out with the reason — switching models says so in the popup too. If upstream answers 400 naming that field, it is stripped and retried once: worst case the level is ignored, not the model unusable.
Context budget: Under Settings → model configuration, every model row carries a "max context" control made of three parts — a slider whose ticks are generated from that model's own window, an exact number box, and a "probe window" button. "Auto" now takes this model's nominal window × 0.8 with no snapping to shared ticks: a local model with an 8K window used to be unable to reach the lowest tick and would fill the whole window, leaving no room for the reply, and now lands on 6553. The number box keeps whatever you type (131072 stays 131072; it is only clamped inside 1K–4M). For Ollama / llama.cpp / vLLM / OpenAI-compatible endpoints, one click probes the endpoint's real window, which is stored as a separate override you can clear back to the endpoint's own value at any time. One value still does two jobs — the auto-compaction threshold and the usage-bar denominator — so the reading can never disagree with when compression fires, and the usage bar is clickable and jumps to that model's row.
Collapsible history summary: once the threshold is passed, earlier turns are compressed into a summary. That summary is still sent to the model in full; in the transcript it folds into a single strip that parses Markdown only when expanded, so a long history does not push the current turns off the screen.
4 Agent Autopilot + 目标模式自主执行Agent Autopilot + Target Mode

Agent Autopilot 是默认的”少打继续”执行层。只要你要求 SLATE Teams 查看项目、修改文件、运行命令、排查 bug、提交代码或生成文件，它会自动进入多轮 Agent Loop，不需要反复发送”继续”。

默认轮数：普通环境任务最多 24 轮；全面排查、项目级、多文件任务最多 40 轮。系统会把工具结果隐藏回灌给模型，让它继续观察 → 执行 → 验证 → 汇报。

干完了就停：轮数是止损线不是预算。交付物逐项验证通过后，模型调用 exit_autopilot（目标模式为 exit_target_mode）显式收口，再给出最终汇报；没做完则继续动手，不靠停发工具或只说“已完成”来结束循环。

Continue Autopilot（默认开，设置 → 自动推进里可关）：轮数用完不等于干完。末轮还在执行工具时，系统把上限往后推 8 轮（最多推 3 次），让它把手上的活做完；末轮空手停笔时，系统把清单剩余项念回给它，催它继续推进或明确写【任务完成】。追加次数有上限，止损线只是被推后，没有被抹掉。

轮数用尽自动续跑：追加的额度也用完、循环真的散场时，系统替你按下那颗「继续跑完」——每一场最多自动续 2 次，续出来的那一场照常走完成通道收口，并弹一条「轮数用尽 · 已自动续跑（第 1/2 次）」告诉你这不是你点的。它等这一场真的空闲下来才按（末轮的压缩与记忆整理还会占着它几秒），你切去看别的会话时也不抢那一屏；万一等不到空闲，就把「继续跑完」交回你手上，不留一头空。两种情况它不动手：这一场切到了「手动审批」档，或设置里那颗开关被关掉——那时续跑条原样挂在那儿等你点。

如果模型只说”我将检查 / 接下来修改 / 是否继续”，系统会自动催它直接调工具；如果没有任何工具记录却口头说完成，系统会要求它先验证或真正动手。

砚流 · 落笔即所见：模型正在逐个 token 写工具参数时，SLATE Teams 会按本地工具 schema 解析这份还没写完的参数，实时演成一行预览——哪些字段已经闭合、哪个字段正在写。它只做预览，半成品参数永不触发执行；几十 KB 的正文类字段一律折叠成行数与字数，不刷屏。

停止是真取消：点击停止会同时关闭模型流与工具调用的流式通道，后端随即终止对应的子进程与在跑任务，不再是“界面停了、活还在干”。被取消的调用会以独立状态记进本地事件账，与正常完成区分开。

回答被截断会说清楚：上游偶尔会让一轮只剩思考、没有正文——思考与正文共用输出上限，思考吃满时正文就没地方写了。这种结局不再被静默咽下去：流收到内容后自然结束、却既没有 [DONE] 也没有 finish_reason 时，这一轮会被标记，收尾时如实报出，原因也分开说（思考占满输出上限 / 上游提前中断）；正文有内容但流提前断的，标注可能不完整。此前这套通知与「继续」入口都挂在 Autopilot / 目标模式上，两种模式都关着时是一点信号都没有，用户只看到“它自己停了”。

回复模式（每个对话可不同）：输入框左下的模式胶囊决定这一场怎么干活，内置四档各有自己的图标与颜色——智能（全部工具，提示词与旋钮都不动，默认）、对话（不调用工具、单轮直答）、经济（只读工具白名单 + 低推理强度 + 收紧轮数）、狂暴（全工具 + 高推理 + 放宽轮数）。切换只改这一场，换会话各用各的，新对话从默认档起；默认档与自定义模式都在「扩展 → 模式」里建与管理。模型也能自己造模式：调 mode_write 建 / 改 / 删，带上追加提示词、工具白名单、推理强度与轮数上限，手动审批档下弹窗把这次改动给你看。白名单是真拦——没开放的工具连原生 tools schema 与文本目录都不下发，模型凭记忆硬调也会在执行口被挡下并说明是模式所限。

本轮改动总结 · 可撤回：这一轮真的往磁盘写过文件（编辑 / 新建 / 追加），模型说完最后一句话后，消息末尾会挂出一张卡片：改了几个文件、各自行数增减，展开能逐文件看 diff。「撤销」把这一轮写过的文件还原成本轮开始之前的样子，本轮新建的文件会被删掉，点下去前先过一道红色确认。你在本轮之后又自己改过的文件会被跳过并如实报出来——撤回不吃掉你自己的修改。原文快照存在 data/round_snapshots/，只留 7 天、超过 2MB 的大文件不存原文（这类文件撤回时同样跳过并写明原因），全部留在本机。

目标模式 是更强的显式闭环模式。需要 80 轮长任务、明确 TODOLIST 和六阶段约束时，点击输入框左侧 ＋ 菜单里的「目标模式」开关，或在消息中提及「用目标模式执行」。

六阶段流程：

  1. 目标理解 → 解析你的需求
  2. 计划制定 → 拆解为可执行步骤
  3. 工具执行 → 自主调用文件/终端/搜索等工具
  4. 验证检查 → 确认每步结果
  5. 汇报总结 → 输出执行报告
  6. 追溯归档 → 记录到 TODOLIST
特性：最多 80 轮自主调用 · 验证通过后模型调 exit_target_mode 收口 · 中途可暂停不丢进度 · 自动建立 TODOLIST（右栏实时展示，顶栏「任务清单」按钮可随时折叠）· 异常自动恢复

Agent Autopilot is the default "do not make me type continue" execution layer. When you ask SLATE Teams to inspect a project, edit files, run commands, debug, commit, or generate files, it automatically enters a multi-round Agent Loop.

Default budgets: ordinary environment tasks can auto-advance up to 24 rounds; broad project-wide or multi-file tasks can auto-advance up to 40 rounds. Tool results are fed back invisibly so the model can continue Observe → Act → Verify → Report.

If the model only says it will inspect/edit/continue, SLATE Teams nudges it to call tools. If it claims completion without any tool evidence, SLATE Teams asks it to verify or actually act first.

Stop when it's done: the round budget is a stop-loss, not a target. Once every deliverable is verified, the model closes the loop by calling exit_autopilot (exit_target_mode in Target Mode) and then writes the final report; unfinished work keeps moving instead of ending on silence or a bare "done".

Continue Autopilot (on by default; Settings → Auto-Advance): running out of rounds is not the same as being done. When the last round was still executing tools, the ceiling moves back by 8 rounds (at most 3 top-ups) so the work in flight can finish; when the model stops without doing anything, the open TODOLIST items are read back to it and it is told to keep going or write 【任务完成】 explicitly. Top-ups are capped, so the stop-loss is pushed later rather than erased.

Auto-resume at the cap: when every top-up is spent and the loop really dismisses, the system presses the "继续跑完" button for you — at most 2 auto-resumes per conversation, and the resumed run closes through the normal completion channel. A toast reports which one it is, so you can see it was not your click. It waits until that conversation is genuinely idle (post-round compression and memory work still hold it for a few seconds) and never steals the screen of another conversation; if it cannot get a window it hands the resume bar back instead of leaving nothing. Two cases keep it hands-off: this conversation is on the Manual approval tier, or the switch is off under Settings → Auto-Advance — then the resume bar simply stays put for you to click.

InkStream — arguments as they are written: while the model streams a tool call token by token, SLATE Teams parses the half-formed arguments against the local tool schema and shows a live one-line preview of which fields are already closed and which one is still being written. It is preview only — incomplete arguments never reach execution; multi-KB text fields fold into line and character counts instead of flooding the screen.

Stop really cancels: pressing Stop closes both the model stream and the tool-call stream, so the backend terminates the matching subprocess or running task instead of "UI stopped, work still going". Cancelled calls are recorded in the local event ledger under their own status, kept apart from successful ones.

A truncated answer says so: upstream will occasionally return a round with thinking and no body — the two share one output ceiling, and a long think leaves no room to write. That ending is no longer swallowed: when the stream produced content and then ended naturally with neither [DONE] nor a finish_reason, the round is flagged and reported as it closes, with the cause kept apart (thinking consumed the whole output budget, or upstream cut the stream early); a reply that did produce text but stopped early is labelled possibly incomplete. Both this notice and the "Continue" entry used to hang off Autopilot/target mode, so with both off there was no signal at all — you just watched it stop.

Reply modes (per conversation): the mode pill at the left of the input bar decides how this conversation works, with four built-in tiers each carrying its own icon and colour — Smart (every tool, prompt and knobs untouched, the default), Chat (no tools, single-turn answer), Eco (read-only tool whitelist + low reasoning effort + a tighter round cap), Turbo (all tools + high reasoning + a looser round cap). Switching changes only this conversation; each session keeps its own and a new one starts from the default. The default and any custom modes are created and managed under Extensions → Modes. The model can mint modes itself through mode_write (create / update / delete with an appended prompt, a tool whitelist, a reasoning effort and a round cap), shown to you in a dialog under Manual approval. The whitelist genuinely blocks — a tool that is not opened is dropped from the native tools schema and the text catalogue alike, and a model calling it from memory is stopped at the execute gate with a note that the mode does not allow it.

This round's file changes, revertible: when the round really wrote to disk (edit / create / append), a card appears at the end of the last message once the model stops talking: how many files changed, added and removed lines per file, and a per-file diff when you expand it. "Revert" restores every file this round touched to its state before the round and deletes the files the round created, behind a red confirmation step. Files you edited yourself afterwards are skipped and reported as such — a revert never eats your own edits. Originals live in data/round_snapshots/, kept for 7 days, never stored for files over 2MB (those are skipped with the reason stated), and never leave the machine.

Target Mode is the stronger explicit loop. Toggle "Target Mode" in the ＋ menu (left of the chat input), or mention "use Target Mode", when you want 80 rounds, TODOLIST enforcement, and six-phase constraints.

  • Reading a playbook is not the same as following it: both the tool summary and the rendered procedure remind the model to actually execute the steps instead of inventing results
  • The YAML subset validator (SAY-1) rejects Tab indentation, anchors, multi-document files, flow {} / [], folded > blocks and !! tags, and reports the offending line number. Broken files stay visible in the panel with their reason instead of disappearing
  • Where to edit: the top bar's Extensions page → the Actions column. "+ New Action" or clicking an entry opens the editor; validation runs as you type with line numbers, and Save refuses a failing draft
  • Every overwrite or delete first copies the previous text to data/actions/.history/ (up to 5 versions per Action). The editor's "History" button shows any version or rolls back to it
  • The model can author one too: actions_write requires author: model inside the yml (the panel badges it "Model-written"), and in "Ask" permission mode the exact content is shown for approval first. "Auto" / "Full access" / "Night Mode" skip the dialog, but the format gate always applies
  • Typing @<id> in the chat box injects the whole flow into that message, capped at 6000 characters; the trimmed remainder is flagged so the model reads the rest with actions_read

Self-evolving tools (tool factory): mcp_factory lets SLATE Teams write the tools it is missing and use them itself. Every product lands in the user data area data/evolved/ — two files per tool, the code plus its manifest — and never in the backend/skills/ source tree: an upgrade cannot overwrite data/, and a running program has no business editing itself. Products older versions left inside the source tree are copied over at startup (copied, not deleted). Manage them under the top bar's Extensions page → the New features column, where each entry states its state: working / disabled / broken (with the line of the syntax error) / shadowed by a built-in tool of the same name.

  • Disabling removes the tool from the model's toolbox entirely, rather than failing when it is called; re-enabling is one click
  • Overwrite, revoke and rollback each take a backup into data/evolved/.history/ (up to 5 versions per tool). The entry dialog's history list shows any version and rolls back to it — and rolling back is itself a write, so a version that no longer compiles is never restored
  • Code that does not compile never reaches the disk (the gate compiles, it never executes on your behalf); creating a tool named after a built-in one is refused on the spot
  • Built-ins win on a name clash: if an upgrade ships a built-in tool with the same name, your generated copy is shadowed and labelled — visible and revocable, no fight with the new version
  • @ mentions, skill_search and the system prompt all carry the currently enabled self-produced tools

Design principles:

  • Pure black-white-gray base — no blue-purple gradients, no excess rounding, no shadow or frosted glass; gold is only an accent.
  • Local-first — data stays local; API keys are used only to call models, and chats, memories and files never pass through a third-party server.
  • Token economy — smart compression, tiered calls, silent processing: old conversation folds into summaries, saving budget without losing the point.
  • Never frozen — four layers of timeout defense covering streaming and tool calls. Slow is waitable; stuck is not.
A term worth pinning down: tokens are the unit an LLM bills and remembers by — the longer the context, the more it costs and the more it forgets.
